# Spec — remote notes use authenticated online-only delivery

**Contract.** `send_note` travels from the MCP shim through an authenticated hub
to a `kudo-intake` connector on the home node. `HUB_AUTH_TOKEN` authenticates
the connection as required by `hub::spec::connection-auth`; no note-specific
credential is sent and no unauthenticated endpoint is enabled. The connector
passes the note to the local receiver and returns delivered or duplicate with
its kino id. Admission, unknown-target, checkout, conflict, and backend errors
are refusals with reasons. An unreachable hub or receiver returns unavailable
and accepts nothing; there is no offline queue.

**Size.** The default body ceiling is 256 KiB, overridable with
`KUDO_INTAKE_MAX_BODY_BYTES`. The sender validates before transport, and the
receiver validates again without relying on the sender's result.

**Listing.** `intake_list` returns the local receiver's remote-note arrivals at
or after an RFC 3339 timestamp, oldest first.

**Why.** A shared connection token is sufficient for the private home-lab
topology and avoids inventing a second note protocol inside the hub. A 256 KiB
initial ceiling accommodates full design notes while remaining bounded and
configurable for real usage.

**Rejected.** Offline queueing, public unauthenticated delivery, an
unconfigurable 16 KiB ceiling, and treating a timeout as a refusal by the
receiver.

**Escape hatch.** Authentication and storage backends can change independently.
A later offline outbox can add a waiting state without changing delivered or
refused outcomes.
