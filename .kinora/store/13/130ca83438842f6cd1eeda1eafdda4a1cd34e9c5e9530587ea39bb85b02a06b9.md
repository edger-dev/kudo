# A node decides whether its workers see only kudo's MCP server

**Chosen.** A worker's launch adds `--strict-mcp-config` only when the node it
runs on says so: `KUDO_WORKER_STRICT_MCP=1` in that node's own environment (its
kudo-node service settings). Unset or any other value: the worker gets kudo's
MCP server alongside the user's own servers, as the CLI would load them. The
console's start request never carries it.

**Why.** Which MCP servers a worker needs depends on where it runs. On the
home lab's yolos, the user's servers add first-run prompts and nothing a check
needs. In the second deployment, every check reads the user's own servers
(chat, issue tracker, dashboards, search), and strict mode dropped all of them:
the first overnight run snoozed all four checks. The default is off because
dropping servers silently is the worse surprise.

**Rejected.** Strict always (upstream `552ee0c`): it breaks any deployment
whose checks use the user's tools. Strict by default, with an opt-out: every
new deployment would start without its tools. A per-node allowlist of server
names: more control, but a list to keep up to date, and nothing needs it yet.

**Escape hatch.** The user's own CLI configuration decides which servers load
when strict mode is off; a node that wants only some of them trims that
configuration.
