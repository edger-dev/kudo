# Spec — stopping the daemon does not stop its jobs

**Contract.** The node daemon's service unit sets `KillMode=process`. Stopping
or restarting the supervisor signals **only the supervisor**; every job it
supervises keeps running and is taken back over on restart through the ordinary
adoption path.

**Why this is not a packaging detail.** systemd's default,
`KillMode=control-group`, signals every process in the unit's cgroup — which is
every job the daemon started. So a routine `systemctl restart` would take down
the servers, builds and watchers the supervisor exists to keep alive, and *a job
outlives any one client* — the property the entire substrate is built on — would
be false exactly when it matters most: while deploying a new version of the
thing responsible for keeping them alive.

**What makes it safe.** Re-adoption is already built and already tested. A job's
pid and the kernel's start time for that pid are on disk, so the returning
daemon identifies the *same* process rather than a recycled pid, and tracks it
by liveness probe instead of a child handle it no longer owns.

**Consequence, stated.** A `terminal`-lens job's live pty is owned by the daemon
and does **not** survive this, by prior decision. Its record, id, scrollback and
ownership do; only the live terminal goes, and its screen falls back to being
reconstructed from the retained capture and says so.

**Rejected — `KillMode=mixed`.** It sends `SIGTERM` to the main process and
`SIGKILL` to the rest of the cgroup, so the jobs still die; it only changes how
abruptly.

**Rejected — sandboxing the unit** (`ProtectSystem`, `PrivateTmp`, and friends).
The daemon supervises arbitrary user processes, so anything confining it confines
them too, in ways whose failures would surface as inexplicable misbehaviour in
unrelated programs. What may run at all is the node rule-set's decision, which
can see the difference between a job and a supervisor; a unit file cannot.

**Enforced, not just written down.** An architecture test asserts the unit sets
`KillMode=process` exactly once, because the line reads like a stray override and
is the kind of thing that gets tidied back to a default by someone who does not
know what it holds up.
