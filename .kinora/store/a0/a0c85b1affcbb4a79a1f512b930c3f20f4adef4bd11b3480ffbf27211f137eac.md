# Finding, 22 Oct 2026: kudo and hub do not build on macOS arm64 without a rustc shim

Building `kudo` and `hub` for `aarch64-darwin` fails in `phon-jit` (`0.2.0-rc.5`; `rc.7` ships the
same source). Its build script, on macOS arm64 only, probes `rustc +nightly --version` and on
success compiles its stencils with `rustc +nightly … --cfg tailcall`. Under a plain stable rustc
(not a rustup proxy) the probe passes by accident, `+nightly` becomes a bogus argument, and the
stencils use `become`, which the stable compiler rejects at parse time even behind a disabled cfg
(E0658). Linux builds emit no stencils, which is why every Linux build is fine.

Fix used, from an earlier project that hit the same thing: a `rustc` wrapper placed first on PATH
in the build. When its first argument is `+<toolchain>`, it drops that argument and sets
`RUSTC_BOOTSTRAP=1` for that call only, then runs the real rustc; every other call passes through
untouched. It has to be on both the package and its dependency-only build (`cargoArtifacts`),
because the dependency build is where `phon-jit`'s build script runs; macOS also needs `libiconv`
for the link.

Today the wrapper lives in a downstream configuration as an override. It belongs in jig's Rust
jig, so every edger workspace builds on macOS arm64. Worth reporting upstream to the `phon`
project too: the stable fallback cannot compile while `become` is in the source unguarded by a
macro.
