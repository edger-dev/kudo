# Spec — one shim per workspace; other nodes are an argument, not another shim

**Contract.** Exactly **one** shim is wired per workspace, and that one shim
reaches **every** node. A node is selected **per request**, by its registry name
plus an optional link
(`hub:bf406db5b660bd595cccdfcec5921121bb5a1ac9281a0d9a5c28be2d7ccc79b4`,
`hub:08c3ce357742ccf578caddcfb6578a92216b515adcfe1ac9de4543406be52cb0`) — never
by wiring a second shim pinned to a second machine.

**Chosen.** One parameterized surface. A shim per machine multiplies the tool
count the agent sees — three `list`s, three `start`s — for **zero** capability,
since the node argument already reaches every machine, and every near-identical
tool is a chance to pick the wrong one. This is the corollary of
kino://a9a94ad3464ebf50c30bffcfe64d4596384d5d122c5dfb3fb992b1aa73cd7eba applied
to deployment rather than to a single face's internals.

**Rejected.** One shim per node, pinned by a default. It was tried and deleted:
agent tool surface is a scarce resource, and duplicated tools are a real cost
rather than clutter. Also rejected: a static per-project node target in
configuration — selecting per request keeps a checked-in project config
machine-neutral, so the same file works from any machine.

**Accepted cost.** The agent depends on the hub being reachable, because node
addressing is hub-only by contract and a node-local direct path was deliberately
removed
(`hub:bf406db5b660bd595cccdfcec5921121bb5a1ac9281a0d9a5c28be2d7ccc79b4`). This is
tolerable because a session runs while the hub is up, and daemons reconnect
forever against it
(`hub:d661c899202c18f1d5a968f14d5c87a9d6b422aa62e450dd2134a1c1bfdec4cc`).

**Escape hatch.** Omitting the link selector takes the node's `stable` link, and
the hub falls back to `stable` when a requested link is absent — so a solo,
single-link setup passes no routing arguments at all.
