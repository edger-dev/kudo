# Finding, 22 Oct 2026: governed jobs on a second host, used to replace the earlier process manager

Context: the second deployment above gained a node on a macOS host (the hub moved there too, on
localhost and the VM gateway only), and every agent session now loads `kudo-shim` as an MCP server
for the job tools. The earlier process manager's main use was named recipes on that host: refresh
a browser session cookie for a service, switch the host's home-manager configuration, read a few
logs. Through kudo: `nodes` lists both hosts; `job_start_adhoc` with an exact argv in the node's
seed rules runs unasked (`done:0 under seed-allow`); the host switched its own configuration twice
this way.

## Gaps against the earlier tool

1. **No node-owned recipes.** `job_start <name>` reads the manifest of the *caller's* workspace,
   i.e. the caller's cwd as a path on the target node. Entries in the node's own manifest cannot be
   started by name from another host, and nothing lists them. The earlier tool had a per-node
   recipe list an agent could query and start by name (`cmd_list` / run by name). Needed: the
   node manifest's manual entries listed by `job_list` (or a `recipes` tool) and startable by
   name from any host, still passing the gate. Today agents must know exact argvs, written down
   outside kudo.
2. **A job that restarts its own node ends `outcome-unknown`.** A configuration switch that
   changed the node's own service restarted it mid-job; the re-adopted job lost its outcome. A
   deploy of the node through the node is a normal operation, so the record should say "the node
   restarted under this job" rather than unknown, and the job's exit should be recovered if the
   process wrote it somewhere.
3. **The default cwd is the caller's.** `job_start_adhoc` without a cwd sent the caller's own
   directory, which does not exist on the target and is refused by the allowed root. Default to
   the node's allowed root, or say in the refusal that a cwd on the target is needed.
4. **Stable argvs.** An argv with a store path breaks on every rebuild; the rules were moved to a
   profile path. A recipe by name (gap 1) removes the problem.

## Worked well

The gate, seed rules from a read-only file, the audit, the approval timeout, and the hub binding
only private addresses. The first real remote command ran within minutes of the node starting.
