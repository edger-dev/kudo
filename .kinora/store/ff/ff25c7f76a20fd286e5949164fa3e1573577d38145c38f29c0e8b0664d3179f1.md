# Spec — a governed job a worker starts is traced in its context

**Contract.** When a worker starts a job on any node, it appends a
**job-start** event to its lease's trace: the node, the job's id there, whether
it waits for the author's verdict, and the argv it asked for. When the worker
sees that job end (waiting on it, or reading it after it ended), it appends one
**job** event: the node, the id, how it ended (`done:0`, `denied:rule`, …) and
the verdict it ran or was refused under (`seed-allow`, `approved-once`,
`rejected-always`, …). The node's audit file stays the authority; the job id
in the trace is the context's pointer into it.

A claim lives longer than a governed node's approval window (an hour against
30 minutes), so a worker waiting for a verdict keeps its item.

**Chosen.** The worker is the one writer that knows the context, and it
already writes the trace; the context reads why a command ran next to what
the worker concluded from it. The job id needs no tag on the node's side: it
is unique there and named in every audit record.

**Rejected.** The node publishing each audit record for the console to write
into the tagged context: it works after the worker is gone, but trace writes
would need the console running. A lease tag carried on the job in moco (one
more field on every job for what the start event already records).

**Escape hatch.** A job whose worker ended before it did is found by its id in
the node's audit; publishing audit records as hub events stays possible later
without changing the trace events.
