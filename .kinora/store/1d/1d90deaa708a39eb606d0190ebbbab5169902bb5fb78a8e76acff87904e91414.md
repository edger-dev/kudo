# Spec — the shim re-dials a dropped hub; a hub restart is not a session restart

**Contract.** The shim holds its consumer lane lazily. When a call fails for a
**transport** reason — the connection is gone — the shim re-dials the hub and
retries that call **once**. If the re-dial fails, the original failure is
reported, naming the address.

A **domain** failure is never retried. A connector's refusal, an unknown node, a
denied job: these reached someone and were answered, and retrying them would
only produce the same answer, or worse, act twice.

**Chosen.** Lazy re-dial on transport failure, at the point of use. A node
reconnects to the hub forever by contract
(`hub:d661c899202c18f1d5a968f14d5c87a9d6b422aa62e450dd2134a1c1bfdec4cc`); a
consumer that does not is the one component in the mesh that a hub restart
takes out, and it would take out an agent session with it for no reason. The
retry is **once**, not a loop: if the hub is genuinely down, failing with an
actionable message beats stalling the agent behind a backoff it cannot see.

**Rejected.** A background reconnect loop with backoff. It adds a task and a
state machine to a component whose entire job is request/response, and it hides
the failure behind a wait instead of reporting it. Also rejected: retrying every
failure — that is how a `job_start` that was refused for a good reason gets
issued twice.

**Escape hatch.** The dial itself is still a startup requirement: a shim that
cannot reach the hub at launch exits rather than starting up degraded, because
there is no node-local path to fall back to
(`hub:bf406db5b660bd595cccdfcec5921121bb5a1ac9281a0d9a5c28be2d7ccc79b4`).
