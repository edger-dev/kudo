# Finding, 20 Oct 2026: the node cannot launch a worker pane yet

A worker is the agent CLI in a terminal pane, started with its own
environment (KUDO_CONTEXT, KUDO_LEASE, …). moco's ad-hoc start
(`StartRequest`) carries only argv, cwd and a deadline: no environment and no
`@Terminal` view. Only manifest-declared jobs get a terminal, and the manifest
has no environment field either.

Phase 1 works around it: `kudo-shim worker <context>` replaces itself with the
CLI in the current pane. For the node to start workers (and the console's
"start a worker"), moco's ad-hoc start needs an environment and a
`human_view`; then kudo-node can build the launch plan on its own machine
(its own shim path and store) and start it as a terminal job.
