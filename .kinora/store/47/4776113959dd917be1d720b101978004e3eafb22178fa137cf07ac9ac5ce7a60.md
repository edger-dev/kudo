# Spec — Kudo MCP exposes live session messaging

**Contract.** Every `kudo-shim` MCP server with a hub address registers one live
session through the hub, using the worker lease as its id or a generated UUID for
a bare session. Registration carries local node, harness, current workspace, and
optional worker context. Workers register in a background retry loop without
blocking startup. A reconnect registers the same session and mailbox again.

The MCP offers `session_list`, `session_send`, and `session_messages` whenever a
hub is configured. Listing returns local and one-hop peer sessions with qualified
ids. Sending takes a target and body, generates or reuses a message id, and returns
`delivered <id>` only after the receiving shim accepts it. Unknown, offline, or
refusing targets return errors. Retrieval drains the current session's pending
messages without promising ordering across concurrent publishers.

A transport failure or timeout refreshes the connection and registration without
replaying an ambiguous send; the original error is returned after a bounded,
best-effort refresh. The caller retries explicitly with the same id. Receivers
retain only an id/content fingerprint after draining, making an identical retry
idempotent and refusing changed content under that id. File-backed delivery and
retrieval are serialized by a crash-released per-session lock.

**Worker delivery.** A worker's session service writes each accepted message to
its file-backed local mailbox before acknowledging. The Stop hook drains pending
messages at a turn boundary and injects their sender, id, body, and reply address
as the next prompt. An open claim and an ended lease retain their existing
priority. Message delivery clears idle waiting without consuming a queue item.
Bare sessions use `session_messages`; no terminal text is injected implicitly.

**Scope.** The hub and shim retain no offline message bodies after mailbox
deletion. No automatic terminal input, multi-hop forwarding, or sender-supplied
identity override is offered.

**Why.** Agents need to discover and coordinate with live work on connected nodes
while preserving Kudo's worker claim/turn invariants and portable MCP behavior.

**Escape hatch.** A harness-specific immediate delivery adapter can be added per
session without changing message routing or acknowledgement.
