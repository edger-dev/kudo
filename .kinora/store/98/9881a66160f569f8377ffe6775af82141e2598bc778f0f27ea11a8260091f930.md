## Phase 0 — preserve the evidence and the contract

- The current code establishes that the worker engine is already separate from
  Claude's launch and hook translation; keep that separation.
- Official Kimi 2.5.2 documentation establishes compatible MCP, Stop,
  PreCompact, UserPromptSubmit, PostToolUse, and PostToolUseFailure surfaces,
  but no Claude-compatible per-launch settings, MCP, strict-MCP, session-id,
  or interactive positional-prompt flags.
- A real `kimi -p` call has already invoked `mcp__kudo__nodes` through the
  existing shim and returned pc, yolo, edger::edger, and edger::yolo.
- Kimi documents SessionStart and PostToolUse as observation-only. Probe the
  actual payloads and do not assume Claude's additionalContext reaches the
  model. Interactive startup remains an explicit implementation problem, not a
  reason to declare headless-only support complete.

## Phase 1 — the boundary and Claude Code, without behavior change

- Move Claude's current launch and hook protocol into its adapter. Keep the
  worker engine, lease ids, queue, and console unchanged. Harness selection is

## Phase 2 — Kimi Code headless, one vertical slice

- Tests first from captured Kimi launch configuration and hook payloads.
- Generate Kimi's MCP and hook configuration, map the node's bypass decision to
  Never Ask (`--auto`, or print mode's default), and translate Stop and other
  replies. Supply the context head through a path that actually reaches Kimi;
  make shell evidence discoverable even where hook output is observation-only.
- Prove two consecutive items as two turns of one lease in `kimi -p`, then
  moved-head refusal, release, turn budget, and shell evidence. Record any
  harness limitation honestly rather than stubbing it.

## Phase 3 — Kimi Code interactive in the console

- Tests first for startup, strict MCP, project-server trust, human takeover,
  and compaction.
- Implement interactive kickoff without confusing it with a human takeover;
  map Kimi's generated session id separately from the kudo lease. Implement the
  node's strict-MCP decision as actually restricting the offered servers, not
  merely hiding their tools from the model.
- Run a worker from the console in a terminal pane on yolo, take it over and
  type, compact it, and verify the lease and trace. Headless success is not a
  substitute for this phase.
