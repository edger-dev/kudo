# Spec — each layer runs against the layer below, or its shipped stand-in

**Contract.** Every layer of kudo can be developed, tested and run with only
the layer directly below it — or an **in-process stand-in that the lower
layer itself ships** — reached through the same seam it uses in production.
Four rules make that hold:

1. **The lower layer ships the stand-in.** A consumer never writes its own
   fake of another layer: kinora ships `memory://` and `file://` mirrors, the
   hub ships a loopback hub, moco a local runner.
2. **One suite, both sides.** A stand-in is exercised by the same assertions
   as the real thing; the real side is opted into by environment (as
   kinora-remote's `KINORA_REMOTE_S3_TEST` is). A stand-in without that shared
   suite is debt.
3. **Optional means optional.** A dependency a feature needs disables that
   feature when absent; only a dependency the layer cannot do without stops it
   from starting.
4. **Configuration is the environment, with local defaults.** One variable
   moves a layer from its stand-in to the real dependency; no rebuild, no
   config file to keep in step.

A full environment (hub, nodes, object store, console) is assembled for an
end-to-end check, not needed for daily work; when it is, its topology is a
moco manifest, so the process manager runs its own development.

**Chosen.** Layered local development. Bringing up every component to work
on one was tried (here and on a workplace project) and ended messy: each
developer recreates the stack, every change waits on all of it, failures in
one layer block work on another. The context store and its mirror already
show the alternative working — tested on `memory://` and `file://`, run
against MinIO, aimed at R2 by a variable.

**Rejected.** A shared, always-on development stack (couples everyone to its
uptime and state). Consumer-written mocks (drift silently; every consumer
writes its own). A dev mode built into each binary that fakes its neighbours
inline (the fake ships in the wrong layer and is never checked against the
real one).

**Escape hatch.** A seam too costly to stand in for (a third-party service
with no local equivalent) is tested against the real thing behind an opt-in
variable, and its consumers degrade per rule 3 when it is absent.
