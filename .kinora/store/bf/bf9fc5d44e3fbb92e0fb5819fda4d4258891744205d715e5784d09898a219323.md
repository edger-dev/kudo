# Plan — process control

**Task:** kino://9fa68946e97641ee0adb10b83029105d5cfefab1c257682460b542dae173d3b4

Built already (moco's engine, read 22 Oct): the exact-argv gate, preflight,
pending jobs with a fail-closed timeout, allow once / deny once (with an
edited argv), and the file audit. Missing: the "always" verdicts, decide /
preflight / pending on the wire, a governed kudo-node, a typed worker start,
the console's approval queue, and the job event in the trace. Each step is
tests → implementation → fresh review → fixes.

## Steps

1. **moco: standing verdicts.** allow always / deny always append an exact-argv
   rule to a writable rules file in the registry's state dir, layered on the
   seed (deny beats allow across both); reloaded on start, so a restart keeps
   them. Specs and task in moco's ledger.
2. **moco: the verdict on the wire.** `decide {id, verdict, edited_argv?}`,
   `preflight {argv, cwd}`, and pending jobs (argv, cwd, who asked, since,
   time left) in the job list; the job connector serves them.
3. **kudo-node governed.** A policy from the node's configuration: seed rules
   (a styx file, from Nix), the allowed root, a 30-minute approval timeout,
   the audit file in the state dir. The home module grows the options; the
   dotfiles seed each node.
4. **The typed worker start** (kino://5720302421d8748ea19b23da1f119f7c0e7514753b340ae5e425fa7e48588b41) in kudo-node; the console's
   start uses it; a node without it is refused as too old.
5. **Shim job tools.** start / tail / wait / kill a governed job on a named
   node (`job_wait` is new), tagged with the lease; a pending start says it is
   waiting for the author, and the job's end appends the `job` trace event
   (kino://e23a8b06aa9331b3f1ffd8df36be1392daf44e93ca20037b50cec6c3132f53e1).
6. **The console's approval queue.** Pending jobs across nodes, newest first:
   node, argv, cwd, the lease and context that asked, time left; buttons for
   allow once / always, deny once / always, and edit-then-allow.
7. **Live.** Redeploy pc, edger and both yolos; a worker on yolo runs a command
   on pc's host node, approved from the phone; the trace shows it; an
   "always" rule survives a node restart.

## Open

- The claim deadline (30 minutes) equals the approval timeout: a worker
  waiting on an approval can lose its claim. Raise the default or let a
  worker extend its claim — settle at step 5.
- Verdicts travel over a hub that trusts its network: any hub client can
  approve. Hub authentication stays a separate decision.
