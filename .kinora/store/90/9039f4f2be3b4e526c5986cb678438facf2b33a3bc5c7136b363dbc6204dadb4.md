# Spec — the local receiver commits each remote note once

**Contract.** A receiver maps short target aliases to dedicated, clean `main`
checkouts. Before writing it applies note admission, requires the target
checkout to be clean and on `main`, and refuses an unknown alias or a checkout
that is not ready. Each note carries a stable opaque id and a content
fingerprint. A first delivery stores one markdown kino in the target's inbox
with author, machine, session, creation and receipt times, fingerprint, and
`status::unreviewed=true`; it then compacts Kinora and makes a local Git commit.
A retry with the same id and fingerprint returns `duplicate` without another
write, including after the note moves out of the inbox. The same id with
changed content is a conflict. No remote push occurs.

**Listing.** The receiver lists remote-note arrivals in the inbox at or after a
caller-supplied RFC 3339 time, oldest first. Note creation and receipt times
must also be RFC 3339 timestamps. Other inbox entries are ignored.

**Why.** Durable local commits make delivery and later triage hands-free while
stable ids make retries safe. Restricting writes to a clean, dedicated `main`
checkout prevents the receiver from committing unrelated work. Checking every
root for an id keeps deduplication intact after triage.

**Rejected.** Writing into a dirty working checkout, treating a repeat as a new
note, deduplicating only within the inbox, pushing notes to GitHub, and making
Git part of the transport contract.

**Escape hatch.** Git commands are isolated behind the current backend's commit
step. A future Kinora backend can replace that step without changing note
identity or delivery semantics.
