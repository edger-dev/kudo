# Design note, 16 Oct 2026: the context kino and the submission shape

Both descend from trialled shapes: the vault State block (case-memory trial, passed 9 Oct) for the head; the orchestrator's artifact core for the submission.

## The context kino

An identity in the context store (root `contexts`, kind `kudo::context`). Markdown body + typed metadata, **written together by the submit tool from one input** so they cannot drift. The body is the head — the State-block grammar, ≤ 20 lines, verdict first:

~~~
# <title>
state:       active | waiting | parked | done — <one line>
where:       <position, verdict first>
next_action: <one action> · who: worker | human | <other>
established:
  - <fact> (evidence: kino id or span)
open:
  - <gap a cold reader would miss>
read-next:   <pointer, only if the head is not enough>
~~~

Metadata (what machines filter on): kind, state, repos as mounts (node, path, ledger store), link to the latest submission.

**Leaves the context kino:** the append-only log of spec-context-unit. The submissions ARE the log (backlinks); a log view renders them. → spec-context-unit amendment, together with "superseded, not rewritten in place".

Queue items: own write-once kinos (root `items`, kind `kudo::item`), link `context:`, body = the ask as typed, state moved by claim / settle kinos. No inter-item dependencies in v1.

## The submission kino

Write-once, one per item worked (root `submissions`, kind `kudo::submission`). Markdown body with fixed sections (Established / Claimed / Ruled out / Gaps / Head as left) so it reads cold; metadata = the typed core, trimmed from the orchestrator's artifact:

| Field | Rule |
|---|---|
| links | `context:`, `item:`, `session:` (the distilled transcript kino), `evidence:` ids, `cites:` project kinos (cite-and-cache), `head:` the version it produced |
| established[] | {claim, evidence[]} — evidence required, else the tool moves the entry to claimed |
| claimed[] | {claim} — accepted, rendered as such |
| rules_out[] | {candidate, because} — optional; nothing to say is legitimate |
| gaps[] | what this worker could not see — optional |
| confidence | optional, 0..1; absent says the true thing; validated when present (orchestrator lesson: required fields produced fake 1.0s) |
| triage | `routine` \| `look` — the phone's glance signal; optional |
| head | **the full new head body** as the worker leaves it (YJ, 16 Oct): deterministic, diffable, no merge logic; the tool stores it as the superseding version. Rejected: per-field delta (merge logic + fork problem); tool-derived head (loses the worker's own where/next wording) |
| usage | tokens/turns if the hook exposes them |

Dropped from the orchestrator's core: `stage`, `decision`, `data{}` — stage-level, post-v1.

## Where structure lives — decision

Typed metadata + markdown body, one input, one tool write (chosen). Rejected: markdown-only with headings parsed at read (no index filtering, parse drift — the vault's limitation); fully structured without markdown (unreadable without the console; inverts "markdown as the disk").

## Plan delta

- Phase 2 = these two shapes + the item kino, the submit tool's single typed input, citation enforcement + the claimed downgrade, the head-as-superseding-version write. Done when: a submission with one unevidenced "established" line lands as claimed; the head's supersedes chain shows the two versions; a log view lists the submissions by backlink.
- spec-context-unit amendments (for the personal session before storing): superseded head not rewritten in place; the log is the submissions; repos declaration = mounts table.
