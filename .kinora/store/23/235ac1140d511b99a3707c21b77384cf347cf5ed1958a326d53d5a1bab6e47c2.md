# Task — MCP session messaging

Implement `kudo::spec::session-messaging` over hub spec
`hub::spec::session-messaging`.

## Done when

- Real shims register automatically, list peer-qualified live sessions, send and
  reply through connected hubs, and redial the same registration.
- `session_list`, `session_send`, and `session_messages` are exposed only with a
  hub and report unknown/offline/refused delivery accurately.
- A real worker Stop hook delivers a file-acknowledged message once at a turn
  boundary without disturbing open-claim and ended-lease behavior.
- Bare sessions drain their local mailbox through MCP; no terminal injection.
- Full workspace, docs, zero-warning clippy, and Nix checks pass with the new hub
  pin; usage and live-only limitations are documented.
