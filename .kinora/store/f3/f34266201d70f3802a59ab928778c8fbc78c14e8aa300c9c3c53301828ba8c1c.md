# Spec — a worker pane starts through a typed node operation, not free argv

**Contract.** A governed node offers one operation besides the gated start:
**start a worker** for `{context, repo?, lease}`. The node checks each value's
shape — the context a full 64-hex id, the repo a plain name (letters, digits,
`-_.`, not leading `-` or `.`), the lease a lease id — and builds the argv
(`kudo-shim worker <context> [--repo <name>]`), the environment (the lease,
the node's own name, the node's hub address) and the terminal view itself,
starting in `/tmp` (or the allowed root, when that does not hold it). Whether
the repo is declared for that context on this node is the worker's check: it
reads the context and refuses an undeclared one. No argv,
environment or working directory chosen by the caller crosses; everything
else a caller wants to run still goes through the gate.

**Chosen.** The values a worker start needs are few and checkable, so the node
can own the command the way it owns `@MOCO_*` tokens: the caller picks within
a typed shape and never writes a command line. moco stays generic; the
operation is kudo's, in `kudo-node`.

**Rejected.** An allowlist of environment names plus approval of each start
(every start a tap, or an "always" per context). Letting a caller that claims
to be the console skip the gate (any hub client can claim it).

**Escape hatch.** A future face that needs another kind of pane gets its own
typed operation, never a widened one.
