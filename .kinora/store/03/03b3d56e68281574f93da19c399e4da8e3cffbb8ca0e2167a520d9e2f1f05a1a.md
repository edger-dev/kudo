# Design note, 16 Oct 2026: the pull worker loop

Settles the phase-1 open question ("which CLI hook is the primary pull loop"): **the Stop hook**, with SessionStart for binding and the tool protocol (an MCP server) for pull/submit. Built only from the agent CLI's own surface — hooks, MCP tools, launcher flags — per spec-worker-pulls.

## The loop — one item per turn

1. kudo-node starts the ordinary interactive CLI in a pane, passing a **worker settings file** (hooks → kudo-shim) and the **kudo MCP config** on the command line. Zero per-repo setup; hooks and tools come from the launcher, never from the repo's own settings.
2. **SessionStart** hook injects the context's head + "you are a worker under <context>; pull". The model calls `pull` → a claim on the next ready item under the bound context.
3. The model works, then calls `submit` → citations enforced, submission kino written, head superseded, claim settled.
4. **Stop** hook: asks for the next ready item under the context. If one exists → block the stop, hand the item as the reason → the session continues as a new turn, cache warm (the *semi* session). If none → stop allowed; the pane idles for a human to sit down at.

## Guards (free from the hooks)

- Stop with an open claim and no submission → blocked: "submit or release first".
- Human types in the pane → **UserPromptSubmit** records "human took over at line N" on the lease; the segment stays traceable; nothing is injected into the session (the human used the CLI's own prompt).
- Crash mid-item → claim deadline expires → item released → next pull takes attempt N+1. The orchestrator's three claim rules port unchanged (refused if key exists; N+1 only after N settled; deadline on every claim). A claim is a write-once kino in the context store.
- Headless: the same hooks fire in print mode (stream-json out) → the unattended adapter is a launcher flag, not a second seam.

## Lease end — decision (YJ, 16 Oct; all four)

The Stop hook lets the session end (instead of handing the next item) when ANY of:
1. **queue empty** for the bound context — the pane idles; a later enqueue starts a fresh lease;
2. **before compaction** — the PreCompact hook ends the lease: the cache goes cold anyway and the head carries over; never work an item on a summarised transcript;
3. **turn or token budget per lease** — set in the worker settings; the cost brake for nights;
4. **human takes over** — the first human prompt ends the worker lease; the session continues human-driven and is traced as such (a later `pull` by the human re-opens a worker lease in the same session).

## Rejected

- One session per item under a supervisor: cold cache per item (the semi-session note already refused it).
- A model-driven loop inside one turn, no hooks: no clean human takeover mid-turn, no Stop guard, a forgotten submit is invisible.

## Plan delta

- Phase 1 = this loop end to end against the real CLI: launcher flags, SessionStart bind, pull/submit MCP tools, Stop-hook handoff, the four lease-end conditions, claims with deadline. Done when: two consecutive items of one context are worked as two turns of one session, a third session end is caused by each of the four conditions, and a killed worker's item is re-pulled after its deadline.
- Phase 2: the hook-trace kino (pull, submit, takeover, lease end, compaction) is the loop's own event log.

## Open, carried

- Deadline length and whether a worker can extend its own claim (heartbeat from PostToolUse) — phase 1 against real item sizes.
- Whether the Stop hook may hand an item from a *different* context on the same repo when the bound context is empty (cross-context semi-session, better cache use) — leaning no for v1: a lease is one context.
- Budget accounting source: the hook payload's usage fields vs counting turns — phase 1.
