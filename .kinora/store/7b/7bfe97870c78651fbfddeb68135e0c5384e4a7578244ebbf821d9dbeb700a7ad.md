## Phase 1 — the shim without a hub

A worker session needs the context store, not the hub. The shim starts
without `KUDO_HUB_ADDR` (or with a hub that does not answer): the worker
tools and hooks work, each job tool answers that no hub is configured or
reachable. A worker session with a hub is unchanged.

Status: done (21 Oct). A worker session dials the hub lazily — when a job
tool first needs it, within 3s, again after a failure — and with no address
lists only the worker tools; the server's instructions say when there is no
hub. A session that is only job tools still needs the hub (bounded 3s dial).
The launch plan's hub is optional, and only the mirror's non-secret settings
are handed on by name: a probe showed the agent CLI passes its environment
to MCP servers, so keys travel by inheritance, never on a command line. Seen
live: a worker with no hub pulled, worked and submitted. Reviewed; fixed.

## Phase 2 — a loopback hub, shipped by the hub

In the hub repo: an in-process hub a test or a single machine can start, the
same protocol on a loopback address. The shim's job-tool tests run against
it, and against a real hub when one is named.
