# Spec — a remote note is admitted only after sender-side safety checks

**Contract.** A remote intake note names a target alias, a nonempty title and
body, and provenance for its author, machine alias, session, and creation time.
It is accepted only when its sender explicitly attests that it contains no code
and no employer-specific information. Deterministic admission rejects blank
required fields, bodies over a caller-configured finite byte limit, fenced or
indented code blocks, and configured sensitive markers matched without regard
to case. Every refusal names its reason.

**Why.** The sending side is the last point where a note can be refused before
its content crosses a network or employer boundary. Semantic judgement belongs
to the sending agent's attestation; deterministic checks provide predictable
backstops without pretending to recognise every kind of sensitive content.

**Chosen.** Keep the byte limit configurable while real note sizes inform the
final default. Rust strings provide valid UTF-8 by construction. Code-block and
marker checks supplement, never replace, the attestation.

**Rejected.** A fixed 16 KiB limit, an unbounded payload, receiver-only
screening, and claims that deterministic patterns can identify all code or all
employer-specific information.

**Escape hatch.** The eventual transport and default size limit are separate
contracts. New deterministic checks may be added conservatively when they have
clear false-positive behaviour.
