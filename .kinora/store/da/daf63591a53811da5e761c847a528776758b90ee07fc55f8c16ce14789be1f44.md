# Spec — every node is governed; a command no rule allows waits for a human

**Contract.** Every `kudo-node` runs its job registry **governed**: an ad-hoc
start is matched on its exact argv against the node's rules before anything
spawns. A matching allow runs; a matching deny never spawns; anything else is
a **pending** job that waits for a human verdict and fails closed (denied)
after **30 minutes**. The verdicts are moco's four: allow once, allow always,
deny once, deny always — the two "always" verdicts append an exact-argv rule
to the node's own writable rules, on top of the seed its configuration ships.
A governed node refuses a start that carries an environment.

**Chosen.** One rule for every node, the sandboxed yolos included: the gate is
what lets a worker run a command on a host the author did not foresee without
handing it a shell there, and a uniform rule leaves nothing to remember about
which node is which. 30 minutes leaves room to see the request on a phone.

**Rejected.** Governing only the hosts (yolo's sandbox would be the only
boundary there, and the node would be a different kind of node). Once-only
verdicts (a recurring check would need a tap every time). moco's 5-minute
default (approvals would need the author watching).

**Escape hatch.** A node's seed rules (from its Nix configuration) pre-allow
what is known to be safe; a worker pane is started by a typed node operation,
not through the gate (kino://5720302421d8748ea19b23da1f119f7c0e7514753b340ae5e425fa7e48588b41).

Open: the hub trusts its network, so any hub client can send a verdict; hub
authentication is its own decision.
