# Spec — a waker starts a worker when a context has a due item and none runs

**Contract.** `kudo-shim waker` runs as a user service on **one** node. Once a
minute it syncs the store and, for each context with an item that **became
due** (an item with a due time now past) and no worker running — no live
lease (traced, not ended, not quiet) and no pane started in the last 15
minutes — it starts one worker on the context's wake node
(kino://4afb77c56fe120a92c8ecb4f01b9a8873e9a41fb8eecb450b9a60e1b1ec327c0) through the node's typed worker start, and records
the pane, as the console does. It wakes for due items only: an ordinary
item still waits for a person to start a worker. The nodes it may start on
are the console's (`KUDO_CONSOLE_WORKER_NODES`).

**Chosen.** One small process owns waking, beside the console on the same
node, using the same launch policy (`kudo_shim::panes`); a face (the
console) holds no scheduling logic, and no node daemon has to read the store.
Waking for due items only keeps unattended spend to what was scheduled.

**Rejected.** Waiting workers alone (nothing wakes once the idle limit ends a
lease). A waker inside every node's daemon (each would read the store, and
nodes would need a rule for which takes which context).

**Escape hatch.** A context that should not wake declares no due items; the
waker can be stopped like any user service.
