- Generate Kimi's MCP and hook configuration, map the node's bypass decision to

- Prove two consecutive items as two turns of one lease in `kimi -p`, then

Status: done. The adapter uses an isolated per-lease home, direct `kudo` MCP
registration, a hooks-only plugin, plain startup context, and an exit wrapper
that settles the lease without pulling more work. Live Kimi 2.5.2 runs proved
two direct-MCP submissions with cited shell kinos, moved-head refusal and
combined resubmission, release, queue-empty, and turn-budget endings. The full
workspace is green, bacon reports zero diagnostics, and fresh review of the
headless fixes found no issues.

## Phase 3 — Kimi Code interactive in the console

- Tests first for startup, strict MCP, project-server trust, human takeover,
  and compaction.
- Implement interactive kickoff without confusing it with a human takeover;
  map Kimi's generated session id separately from the kudo lease. Implement the
  node's strict-MCP decision as actually restricting the offered servers, not
  merely hiding their tools from the model.
- Run a worker from the console in a terminal pane on yolo, take it over and
  type, compact it, and verify the lease and trace. Headless success is not a
  substitute for this phase.

Status: done. Kimi interactive workers use a delayed, split-write Kitty Enter
kickoff through `script -e`; the input bridge accepts both raw and PTY-normalized
console Enter. Strict mode proved `/mcp` contains only kudo, and repos with
project MCP servers are refused rather than implicitly trusted. Real PTY runs
proved direct submission and evidence, Ctrl-S takeover with release, and
PreCompact lease settlement. A console-driven node connector run started a
worker, observed its submission, and accepted input. Fresh review found no
remaining issues; the workspace and diagnostics are green.
