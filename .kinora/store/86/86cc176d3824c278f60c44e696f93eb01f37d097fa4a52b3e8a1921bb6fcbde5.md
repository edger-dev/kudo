# Note, 22 Oct 2026: the earlier process manager's console — its UX, to carry into kudo's console

The author finds this console better than kudo's today. This note describes what it does for the
person using it, so kudo's console can be rebuilt from the intent. No code crosses. The earlier
console polled a hub for nodes and mounted one module per capability (processes, agent sessions,
governed commands) for the selected host, plus a cross-host health dashboard.

## Shell

- Left sidebar, main column beside it. The main column has a top bar, then a horizontal split:
  the active view on the left, a drag handle, a reading pane on the right. The reading pane exists
  in every view. An approvals tray slides over from the right.
- Sidebar: a brand row; a first group with "dashboard" and "inbox"; a second group "hosts", one
  entry per connected node sorted by name ("no nodes" disabled when empty). Collapses to an icon
  strip (Ctrl/Cmd+B or a panel button); collapsed entries get tooltips. Hosts get distinct icons
  by kind (a laptop, a NixOS host, a container, a generic server) so they read when collapsed.
- Narrow screens: the sidebar becomes a slide-over drawer. Nothing else adapts (a gap).
- Top bar: sidebar toggle; a breadcrumb (`app › dashboard`, `app › host › module`); when a host
  has more than one connection label (stable / dev), small link buttons to switch, defaulting to
  stable; a warning line only while the hub is unreachable; the approvals badge; a theme toggle.
- Theme: system / dark / light, remembered in the browser, applied instantly.
- Host view: a tab strip "processes · sessions · commands". The chosen tab carries over when the
  host changes. If the selected host disappears, the first live host is selected.

## Views — the question each answers

**Dashboard — "Is everything up, and is anything crash-looping?"**
- Summary strip: one overall status dot (worst state anywhere) and five big numbers with small
  uppercase labels: nodes online/total, inbox count, running, crashed, total restarts.
- Cards in a responsive grid, grouped under section headers. Each card: a coloured left border
  and dot, host name, uptime % right-aligned, one detail line ("N running · N crashed · N
  restarts" / "reachable" / "offline"), and a thin uptime sparkline.
- Scoring: crashed or ≥ 20 restarts is critical; ≥ 3 restarts or restarting is a warning; offline
  is critical; CPU is deliberately not scored. A host once seen stays listed when it goes offline.

**Processes — "What is running on this box, and can I bounce it?"**
- Toolbar: live counts ("N running · N stopped · N crashed"), a filter on name or workspace, and
  "clear stopped".
- Table: scope, workspace, name, autostart, state (coloured), pid, port, cpu %, mem, restarts,
  actions. Numbers right-aligned in tabular digits; "-" for missing. Sorted by workspace then
  name; system-scope rows last, on a darker tint, below a thicker rule.
- Row actions: stop when running, else start (not for system rows), and restart. Action buttons
  never select the row. Hover previews the row in the reading pane; click opens it live.

**Sessions — "Which agent sessions ran here?"**
- "Sessions (N)" with a refresh button. One line per session: title (or "(untitled)") · message
  count · last folder of its working directory, truncated with an ellipsis. Newest first.

**Commands — "What did agents run here, and what is waiting on me?"**
- Toolbar: "N jobs · N awaiting approval", and the outcome of the last action.
- Four stacked sections, each with a small uppercase header and its own empty sentence:
  live jobs (state badge + command line); pending approvals (command, requester, four verdict
  buttons); allowed recipes (name, approval-mode badge: auto in green, otherwise amber, command);
  history (last 30 verdicts, newest first, verdict badge + command).

**Inbox** — a placeholder listing the drop recipients; never designed.

## The reading pane — hover to peek, click to open, pin to keep

- Openable: a process, a command job, a session. An item is named by kind + host + connection
  label + id, so the same id on two hosts is two items.
- Columns side by side: *Hovered* (a cheap preview, no live connection, one summary line and a
  hint "click to open live · pin to keep"); *Selected* (the last click, live, replaced by the next
  click); *Pinned* (one column per pinned item, × to unpin, no duplicates).
- Column header: role in small caps, "host/id" truncated, a pin or × button.
- Controls: "all columns" fits every column to the width, or "N per view" sizes columns to 1/N
  with horizontal snap-scrolling (each at least ~280px); a fullscreen button hides the list; the
  drag handle resizes the pane (320–1200px, default 560).
- Process view: coloured state, name, workspace; a line of pid / port / cpu / mem / restarts /
  autostart; start / stop / restart; two small sparklines (cpu, memory); output as the last few
  hundred log lines, or the raw screen grid for a terminal process.
- Job view: state badge, "via <verdict>", duration; the command; cwd · requester · run id; kill
  while running, the verdict buttons while pending; output appended, keeping the last 64 KB.
- Session view: "title · N messages", paged 200 at a time; each message a fixed-width role label
  (user in blue, assistant in green) then wrapped text.
- Gone items say so plainly ("not running", "no longer tracked", "not available").

## Approvals — the part to keep exactly

- A background watcher for the whole session merges pending commands from every host into one
  queue, newest first, with a stable tie-break so rows never move under the cursor.
- An always-visible badge in the top bar with three states: muted "approvals · none"; an amber
  pill "N approvals"; red "approvals · unreachable" when a host cannot be reached and nothing is
  queued. A real count wins over trouble. The tooltip explains the state. The point: a
  trustworthy zero is told apart from "unknown".
- Clicking it opens the tray over a dimmed page: "APPROVALS (N)", the last outcome, and a red
  line naming any unreachable host ("retrying").
- Each pending row: host, requester, how long it has waited, the full command, the working
  directory, and four verdicts — allow once, allow always, deny, deny always (deny ones in red).
  Hovering a "once" says no rule is written; hovering an "always" spells out the exact rule it
  will write (this exact argv, this node only).
- After a verdict an outcome note appears; the tray stays open even when the queue empties, so a
  failed verdict never looks like success. On a lost connection the queue clears, rather than
  showing asks that can no longer be decided.

## Live updates

Everything was polled (hosts 3 s, dashboard 1.5 s, processes 0.8 s, commands 0.7 s, approvals
1.2 s, sessions 5 s), each list and viewer on its own connection; previews opened none. Kudo has
a hub event channel now, so it should push where it can and keep polling only as the fallback.

## Visual language

Dense 13px monospace, tabular digits, 10–11px uppercase section labels with letter spacing.
Green = running / exit 0 / auto / allowed; amber = starting / pending / warning; red = crashed /
non-zero / killed / timed out / denied / critical; grey = stopped. Rounded pill badges. Errors as
full-width red bands, success as green inline notes. Deeper green and amber in the light theme for
contrast; themed, higher-contrast scrollbars.

## Rough edges not to copy

- No follow-tail anywhere; transcripts open at the oldest page.
- Nothing in the URL (host, tab, pins), pane width and sidebar state not remembered.
- No keyboard navigation of rows; no confirmation for stop, kill or an "always" verdict.
- History without timestamps or requester; durations in raw milliseconds; jobs unsorted.
- Approval age shown, not the time left before the ask times out.
- Notes and error bands never clear; no Esc to close the tray.
- The split pane does not adapt to a phone; dashboard cards do not link to their host.
- No path back to "follow system" theme once toggled.

## What this suggests for kudo's console

- Keep: the approvals badge + tray (it is the face of the governed-job work); hover / select /
  pin in the reading pane; the dashboard's "worst state first" summary; per-view empty sentences;
  stable ordering; host icons by kind.
- Map: hosts → kudo nodes (peer-hub names included); sessions → leases and their transcripts;
  commands → governed jobs; the inbox placeholder → kudo's inbox root, which is real now.
- Add what was missing: follow-tail, newest-first transcripts, state in the URL, a phone layout
  where the reading pane becomes a full-screen drill, push via the event channel.
- Open: whether the three-pane context layout and this host-centric shell are one console with two
  arrangements (layout as a value), or the host shell is a second view in the same arrangement.
