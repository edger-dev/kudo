## Phase 1 — note admission

Create a shared intake crate and tests for required fields, attestation,
configurable byte limits, code blocks, and sensitive markers. No network path.

## Phase 2 — local receiver

Implement alias resolution, stable note identity and deduplication, provenance
and unreviewed metadata, durable writes into a dedicated `main` checkout, and
time-based arrival listing with the current Git backend.

## Phase 3 — authenticated transport

Settle the hub authentication mechanism and default note-size limit. Add the
home connector and online-only delivered/refused/unavailable replies without
exposing an unauthenticated endpoint.

## Phase 4 — MCP and end to end

Expose `send_note`, run real cross-process delivery and refusal checks, update
user documentation, and verify offline calls return unavailable without writes.

## Status

Phase 1 is ready. Phases 2–4 remain planned; phase 3 is blocked on the open
authentication and size-limit decisions.
