# Design note, 16 Oct 2026: traceability of agentic runs

## Trace layers, raw → derived (each a kino or blob with a typed link to the layer below)

| Layer | What | In kudo | Authored by |
|---|---|---|---|
| raw transcript | the session jsonl | moco blob, content-addressed — **filed in v1** (YJ, 16 Oct): one put per session, phone never reads it | the CLI |
| distilled transcript | turn per line `{line, speaker, kind, text, ts}`; line numbers are the address space for spans | derived kino, deterministic → dedupes; `derived-from:<blob>` | code, no agent (a session distills before it derives) |
| lease / segment | which stretch of a session worked which item | **known by construction**: pull at line N, submit at line M — no opt-in markers to infer (segmenting at markers becomes unnecessary under the pull seam) | the pull loop |
| asked | what the human enqueued; what the worker was handed | the queue item kino, write-once, state by append — the orchestrator's boundary object ("records what was asked") falls out for free | kudo's context engine, on behalf of the enqueuer (the human via the console, or a worker filing a follow-up); the hub only routes the call (YJ correction, 16 Oct) |
| submission | established / ruled out, each with evidence (span into the distilled kino, kino id, URL) | write-once kino, typed weak links (`context:`, `run:`, `session:`, `item:`, `evidence:`) | the worker, at submit |
| head | the resume block | superseded head linking to the submission | the submit tool |

## "Fully traceable" as a test

- Forward (phase 2 done-when): from any line of a head → the submission that wrote it → its lease + span in the distilled transcript → the raw blob → the queue item that asked for it.
- Reverse (phase 4, the session regroup): from any session → every context it touched.

## Who authors the trace — decision

1. **Chosen for v1: the worker submits; the submit tool enforces citations.** Evidence must resolve (span within the distilled kino's line range, existing kino id) or the submit is refused — the rule the orchestrator's harness applied to derivations, moved into the tool. An "established" line without evidence is accepted but **downgraded to "claimed"** (two slots: established / claimed, plus ruled-out) — flag-don't-conclude made mechanical.
2. **Floor under 1, also v1: a mechanical hook trace.** Pull/submit events, tool-call counts, files and repos touched, from the CLI hooks; a kino too. A submission that claims more than the hook trace supports is visible in the console without a judge.
3. **Post-v1: an observer derives post hoc** (the orchestrator's distiller + deriver). Independent of self-report, but a second agent per run and inside the judges/second-opinions fence. Slots in later as a second submission kino citing the same distilled transcript — nothing in v1 blocks it.

## Scope notes

- Only workers under a context are traced in v1. An ad-hoc session is traced only by opting in from inside its own transcript (carried design); the watcher that files shallow observed runs is post-v1.
- Token/cost metadata per submission: record if the CLI hook exposes it (cheap); otherwise post-v1.
- Privacy: transcripts in the personal S3 store are private by tenancy; the encrypted-root gap (see 15 Oct) applies to any shared workplace store.

## Plan delta

- Phase 2 done-when gains the forward trace test; the submit tool gains citation enforcement + the established/claimed downgrade; the hook trace kino is part of phase 1's pull loop (it is the loop's own events).
- Phase 3: the raw transcript blob is the first real moco S3 object — the tracer bullet's transcript must be readable from the console on the second node.

## Open, carried

- Span addressing when a transcript is still growing (a lease submits mid-session): distill incrementally (append-only distilled kino superseded per submit) or distill once at session end and let early submissions cite line ranges of the final kino — phase 2 against the real CLI.
- Whether the hook trace and the submission are one kino or two (two keeps "what happened" mechanical and "what it means" authored; leaning two).
