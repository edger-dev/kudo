# Spec — a standing verdict and a kill take a second tap that states the effect

**Contract.** "allow always", "deny always" and killing a job do nothing on
the first tap: the button turns into a confirmation that says exactly what
the second tap does — for an always verdict, the exact argv rule it writes
and on which node only; for a kill, which job on which node. A second tap
within ten seconds acts; anything else (time passing, another tap elsewhere)
cancels. Once verdicts, edit-then-allow and typing stay one tap.

**Chosen.** An inline second tap, not a modal: one thumb, no dialog to
dismiss, and the text the author must read is where the finger already is.

**Rejected.** No confirmation (a mis-tap writes a permanent rule or kills a
running job); a browser `confirm()` dialog (blocking, unstyled, and easy to
tap through).

**Escape hatch.** A wrong standing rule is removed from the node's rules
file; the confirmation lowers the odds, the file stays the authority.
