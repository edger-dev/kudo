# Spec — the agent shim is a stdio proxy whose cwd is its workspace identity

**Contract.** The agent face is a **stdio** MCP server launched as a child of the
agent session, one per workspace. Two properties define it:

- **It holds no state.** Every operation is proxied to the engine, which owns the
  registry, the rule-set and the audit
  (`moco:66b68fd402b1ff45e6782ec73f4211b845c29d498058239e66b7b946b60f490c`).
- **Its working directory is its workspace identity.** Launched as a child of the
  session, it inherits the project directory for free — so naming the right
  workspace requires no configuration at all.

The shim adds **no capability of its own**. Its tool surface is the engine's Func
surface, minus what only a human may call: approval decisions stay off the
agent's surface entirely
(`moco:08fb4168eb094a53a5d6208430066d0f89d891073e1b24dda3ace5c81fe56db2`).

**Chosen.** Stdio plus per-session launch, because **cwd is the one piece of
identity that arrives without being announced.** Workspace ownership is the
engine's contract
(`moco:0d85bf8a00d18597ab8446e3ff9a95c7e1a25e7e0866cf33f03f4509c2f57c2f`); the
shim's only job on that axis is to name the right workspace, and inheriting cwd
does it with zero config and nothing to get wrong.

**Rejected.** One shared HTTP/SSE MCP endpoint. Nothing about a shared connection
carries a working directory, so every session would have to *announce* its
workspace — identity becomes manual configuration in every project, and a
mis-set value operates silently on the wrong checkout. Also rejected: the shim
caching job state, which would let a second reader see a different world from the
engine; one observable substrate means exactly one.

**Escape hatch.** A caller needing a workspace other than its own passes a
fully-qualified id and gets the engine's access rules unchanged
(`moco:bb38e0d68b4090f86ae94c4ca44100c4afbfd41ffce285b61f50c599dd3e4cc2`) — reads
are node-global, writes refuse a foreign workspace. The shim never widens that.
