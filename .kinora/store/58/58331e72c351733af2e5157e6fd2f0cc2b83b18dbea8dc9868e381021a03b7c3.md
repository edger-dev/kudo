# Task — the first working kudo: a context-bound pull worker and its console

Make kudo the place agentic work is **started and followed**, instead of a
terminal in a notes checkout. This is the umbrella item for the first working
version; it is a rebuild that reconsiders decisions, not a port — three
prototypes (a GUI shell over the agent CLI, a curated-writing site on a kino
pipeline, and a staged-workflow orchestrator) proved some of them and
disproved others, and only intent crosses over from any of them.

**Plan:** kino://c0d2c76488b561c631bc29b995424ef3e8b9c3d3fdbad5a2db4896bf72b48c0d — nine phases, each sized to a night session, each leaving
the ledger committed so the next session starts cold.

**The tracer bullet** (what "working" means): open the console → pick a
context → start an agent worker on a node, in a terminal pane, bound to that
context → watch it pull its first item, work, and submit → start a second
worker in another repo under the same context → read the context's resume
block and find both workers' results in it.

## Carried as design, in neutral terms

- Registry objects are write-once; a run is a prefix of appended objects.
- A session opts in from inside its own transcript and attaches to the work it
  names — here, to a context.
- The work declares the repos it spans; routing a session to its work is a
  path match against that declaration, never a routing table.
- An observed session is distilled mechanically before anything derives from it.
- A worker's submission states what it established *and* what it ruled out.
- The hub is the stable boundary; a daemon owns processes, a face consumes.

Explicitly **not** in this version: staged workflows, rounds, claims on
stages, routed branches, judges, second opinions, evaluation bands. They are
a later layer over contexts, and nothing here may assume them.

## Done-when

- The tracer bullet runs end to end on two nodes, from the console, with the
  context store on the hosted object store.
- A worker is the ordinary interactive agent CLI in a pane; its pull loop uses
  only the CLI's own hooks and tool protocol.
- A context's resume block is rewritten by submissions and reads cold.
- The console is a face: every capability it shows is an engine call over the
  hub, and a second face could show the same without copying logic.
- A governed job on a named node is started from a context, approved from the
  phone, and its audit is in the context's trace.
- A due-dated item waits until its time, wakes a worker, and closes with
  pass, fail or snooze.
- One week of the author's home-lab work ran from kudo, and the friction it
  produced is filed in the `inbox` root.
- Each realizing module cites its spec.

## Known-open, to settle in the phases

- **The pull loop's exact hook.** The CLI's stop hook can hold a session open
  by handing it the next item; whether that or a session-start pull is the
  primary loop is decided in phase 1 against the real CLI.
- **What a worker submits.** The minimum is a delta to the resume block plus
  a log entry with evidence; whether submissions carry typed slots (what was
  established / ruled out) from day one or grow into them is a phase-2 call.
- **Object-store backend shape in kinora.** Declared here, built there; its
  own task lives in the kinora ledger and is cited from the plan.
- **Budget.** Personal subscription, night sessions, phone-driven. Phases
  that do not finish in one session must still leave a committed ledger.
