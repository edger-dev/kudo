# Spec — the Stop hook drives the pull loop; a lease is one context and ends on four conditions

**Contract.** A worker's pull loop is built from the agent CLI's own surface. The
launcher passes a worker settings file (hooks) and the kudo MCP config on the
command line, so a repo needs no setup of its own. The loop:

1. **SessionStart** binds the session to its context and injects the context's
   head with "you are a worker under <context>; pull".
2. The model calls the MCP tool `pull` (a claim on the next ready item under the
   bound context), works the item, and calls `submit`.
3. **Stop** asks for the next ready item under the *same* context. If there is
   one, it blocks the stop and hands the item over as the reason, so the session
   continues as a new turn with the cache warm. Stopping with an open claim and
   no submission is refused ("submit or release first").

A lease is **one context**: the Stop hook never hands over an item from another
context, even in the same repo. The lease ends, and Stop lets the session end,
when **any** of these holds:

- the bound context's queue is empty (the pane idles for a human);
- **PreCompact** fires (no item is ever worked on a summarised transcript);
- the lease's turn or token budget, set in the worker settings, is spent;
- a human types in the pane (**UserPromptSubmit** records the takeover line; the
  session continues human-driven and is traced as such).

A claim is a write-once kino with a deadline. A crashed worker's item is
released when the deadline passes and re-pulled as attempt N+1.

**Chosen.** The Stop hook as the loop: it is the only point where the CLI can be
held open without injecting input, and it gives the open-claim guard and clean
takeover for free. One context per lease keeps a lease's trace one context wide.

**Rejected.** One session per item under a supervisor (a cold cache per item). A
model-driven loop inside one turn with no hooks (no takeover, no guard, a
forgotten submit goes unseen). Handing over items from another context when the
queue is empty (better cache use, but a lease would span contexts and the trace
would have to regroup by session).

**Escape hatch.** Headless runs use the same hooks in print mode; the unattended
adapter is a launcher flag, not a second loop. Whether a worker can extend its
own claim (a heartbeat from PostToolUse) and the deadline length are open, to be
settled in phase 1 against real item sizes.
