# Finding, 22 Oct 2026: due-dated checks in a second, separate deployment

Context: a second kudo deployment on another machine (its own local, git-backed context store, no
mirror, no link to the home hub or bucket), built from upstream `8948da2`. One governed node, the
waker, the console, one context "checks" bound to a notes repository. It runs as a shadow of an
existing script-based check log for a week (22–29 Oct): every check goes into both, the old log
stays the source of truth, and the kudo worker only reports. A test check woke on time, was
claimed, run, closed `pass` and the head rewritten (about 30 s of work). Nine real checks are
queued from 23 Oct.

## What got in the way

1. **A command's output is not evidence.** A check's result is nearly always "I ran X and saw Y".
   Evidence accepts only cited kinos, earlier submissions and URLs with a host, so every check
   verdict lands as *claimed*. For checks this is the normal case, not the exception. Options:
   the hook trace's recorded tool call as evidence (it is already the loop's own record), or a
   span in the session transcript (planned for later).
2. **A finished worker's pane never exits.** With `KUDO_IDLE_LIMIT=0` the lease ends, but the
   agent CLI stays open, with all its MCP servers, holding the node unit's process group (it kept
   an old service unit alive after a restart until killed by hand). A woken worker should end its
   session when its lease ends and nothing is ready.
3. **The agent CLI's first-run prompts block an unattended pane.** Seen twice: approving a
   project-scoped MCP server found in the repository (`.mcp.json`), and a "try the new
   fullscreen renderer?" promotion. Nothing answers them, so the worker sits silent until the
   no-repeat window passes. The launcher could pass the CLI's options that skip or pre-answer
   these, or the waker could detect a pane stuck at a prompt (no trace after N seconds) and say so.
4. **The 15-minute no-repeat counts from a pane that was killed.** A stuck worker killed by hand
   still delays the next wake by the full window.
5. **The waker's start line says "woken workers default to yolo"** on a node with no such host;
   the default should name the node it would really use.
6. **No correction for a closed check.** The old log lets a wrong verdict be superseded by a later
   event with a note. In kudo a closed check can only be followed by a new check referencing it.
7. **No link field.** The old log carries a link to the issue a check belongs to; in kudo it goes
   into the check's text.
8. **Permissions for unattended workers.** The node did not bypass permissions; the repository got
   a read-only allowlist instead (chat and dashboard reads, read-only git and file tools). Worth
   a spec line: what a woken worker may do unasked is the repository's allowlist, not the node's.

## Open
