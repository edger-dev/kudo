# Plan — the console on the phone

**Task:** kino://28edd6ef4c3ea46bc5288a17455f86694b43ea25da045e629cd4d6c287c9af5d

Each step is tests → implementation → fresh review → fixes.

## Steps

1. **moco: a job listing says what each job runs.** The job list carries
   the argv, the directory, the verdict it ran under and how long its
   current phase has lasted, so a node view needs no call per job. A spec in
   moco's ledger; kudo bumps its pin.
2. **The shell.** A stylesheet of colour tokens (light, dark, following the
   system; the toggle remembered per browser), the dense monospace visual
   language, a top bar (back, where you are, the badge's place, the theme
   toggle) and a sidebar of contexts and nodes. The layout value grows its
   narrow arrangement — one pane, chosen by the selection — and the
   selection grows the view, node, job and context tab.
3. **The URL.** The selection written to the fragment and read on load;
   drilling in pushes history, so back steps out; a stale fragment selects
   nothing.
4. **Approvals.** The badge (none / N / unknown), the tray (stable order,
   unreadable nodes named, last outcome, stays open, Esc closes), replacing
   the inline queue; the always verdicts take a second tap stating the rule.
5. **The node view.** A node's jobs (waiting, running, recently ended); a
   job's output, followed while it runs; kill after a second tap. Console
   server functions read the node's job connector.
6. **Docs and live.** The console chapter rewritten; rebuilt and restarted;
   a day of phases 5–6 work followed from the phone — the author's.
