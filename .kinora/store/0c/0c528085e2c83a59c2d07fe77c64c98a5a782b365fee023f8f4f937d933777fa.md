# Finding — a node's own name is not unique across peer hubs

Seen building the waker, 22 Oct. A worker names its node as the node knows
itself (`KUDO_NODE`, the node daemon's `NODE_ID`): pc's yolo and edger's yolo
are both `yolo` to themselves, while pc's hub sees edger's as `edger::yolo`.
Repo declarations (`context repo add … --node`) refuse `::`, and record the
worker's local name — so a repo declared on edger's yolo reads as one on
pc's, and a wake node that defaults to a repo's node starts the worker on
the wrong host. Fix: name nodes uniquely (NODE_ID `edger-yolo`), or record the
hub-qualified name the console and the waker route by.
