# Task — WebSocket transport for hub and Kudo

Add native WebSocket access so a remote Kudo session can dial
`wss://hub_edger.yjpark.org` without client-side `cloudflared`.

## Done when

- The hub serves `HUB_WS_ADDR` beside TCP with identical authentication and routing.
- Kudo accepts `ws://` and `wss://` in `KUDO_HUB_ADDR` and authenticates after opening the lane.
- Optional Cloudflare Access service-token headers are supported as a pair.
- Real WebSocket tests pass alongside all TCP tests, with zero warnings.
- Documentation gives the Cloudflare Tunnel configuration and Incus setup.
