# Spec — ordinary work auto-starts only on an explicit wake node

**Contract.** A context with an ordinary ready item and a declared wake node
gets one worker started automatically on that node when no worker is live or
starting. A context without a declared wake node keeps the existing behavior:
ordinary work waits for a person. Due checks continue to wake on the declared
wake node, the first repo node, or the waker's own node as before. Starting a
second worker while a lease is live or a pane is starting is forbidden, so a
context is serial by default.

**Why.** Console-created implementation contexts should execute without a
manual Start worker action, without opting every existing context into
unsolicited execution and without concurrent edits.

**Rejected.** Starting ordinary work on every context, a daemon per context,
parallel workers by default, or changing due-check fallback rules.

**Escape hatch.** A later explicit concurrency policy can permit independent
worktrees or declared write scopes.
