# Spec — an established line needs evidence that resolves, or it is claimed

**Contract.** A submission is one typed input: what the worker
**established** (each line with its evidence), what it only **claims**, what
it **ruled out** and why, the **gaps** it could not see, and the full new
head. The submit tool checks every evidence entry on an established line:

- a **kino id** must resolve — in the context store, or in the ledger of a
  repo the context declares; a kino from a repo ledger is copied into the
  context store with its origin named (cite-and-cache), so the context reads
  whole without the repo;
- a **URL** (`http://` or `https://`) is accepted as given.

An established line with no evidence that passes is **moved to claimed**, not
refused: the submission lands, and reads as what it is. The submission's body
is rendered from the input in fixed sections (Established / Claimed / Ruled
out / Gaps), so it reads cold.

**Chosen.** Enforcement in the tool, by downgrade. The orchestrator's harness
proved that an unchecked "established" drifts into confident prose; refusing
outright makes a worker invent citations to get through. Downgrading keeps the
honest submission and makes the claim visible as a claim. Transcript spans are
the evidence the 16 Oct trace note expects, but transcripts reach the store in
phase 3; until then a span does not resolve and its line is claimed.

**Rejected.** Kino ids only (a worker would file a kino for every test run it
cites). Any non-empty evidence (citations stop meaning anything). Parsing the
markdown head for evidence (parse drift; the typed input is the contract).

**Escape hatch.** A new evidence form (a transcript span, a moco blob hash) is
one more resolver behind the same check; until it exists, its lines are
claimed, never lost.
