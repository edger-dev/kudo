## Draft issue for phon: `phon-jit` fails to build on aarch64-darwin with a plain stable rustc

On macOS arm64, `phon-jit`'s build script (0.2.0-rc.5; rc.7 has the same
source) probes `rustc +nightly --version`. When `rustc` is a plain stable
compiler and not a rustup proxy, as in Nix builds, the probe succeeds by
accident: `+nightly` is not a toolchain selector there. The script then
compiles its stencils with `rustc +nightly … --cfg tailcall`, and the stable
compiler rejects `become` at parse time even inside a disabled cfg (E0658), so
the stable fallback cannot compile either.

Suggestions: check that the probe's output really names a nightly compiler
(not only that it exits 0); and keep `become` behind a macro (or in a file only
included under the cfg) so the stable path parses. Linux is unaffected because
it emits no stencils.

Workaround in use: a `rustc` wrapper that drops a leading `+<toolchain>` and
sets `RUSTC_BOOTSTRAP=1` for that call.
