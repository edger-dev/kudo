# Spec — a node is a second view in the console: its governed jobs, followed

**Contract.** Beside the contexts, the console lists the nodes the hub
reaches (peer-hub names included), each with an icon by kind. Selecting a
node shows its jobs: waiting for a verdict, running, and recently ended,
each with state, the argv (shell-quoted), its directory and how long it ran.
Selecting a job shows its output, newest at the bottom and followed while it
runs (the view stays at the end unless the author scrolls up), and a kill
while it runs (second tap, kino://3cebbf2e8034b89c65bb3dda9ae2be880cf6c5ba2cd928b559e7fb6dd03579f5). Jobs are read from the node's
job connector through the console server; nothing is cached across nodes.

**Chosen.** One shell, two views — contexts stay the main view, the node
view answers "what ran here, and what is waiting on me", mapped from the
earlier console's commands tab onto governed jobs.

**Rejected.** A separate host console (two shells to keep in step); leaving
nodes out of v1 (the job a worker started on another node could not be
followed from the phone).

**Escape hatch.** Processes, sessions and the health dashboard of the
earlier console arrive later as more renderers in the same node view.
