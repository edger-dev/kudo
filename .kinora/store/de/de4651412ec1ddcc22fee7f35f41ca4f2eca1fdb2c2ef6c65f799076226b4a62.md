# A worker re-probes a missing tool before giving up on it

**Chosen.** A worker's claim prompt says: an MCP tool that seems missing may
still be connecting. Wait and look again (at least twice, a minute apart)
before snoozing, failing, or reporting the tool absent, and say in the note
that it was re-probed.

**Why.** In the second deployment, workers reported the hosted connectors
"still connecting" at session start and usable a little later; checks
concluded "no such tool" from that first look. A rule in the prompt is cheap
and covers any slow server.

**Rejected.** Holding the kickoff prompt until every MCP server reports
connected: the CLI gives no clean readiness signal to wait on, so the wait
would be a guess. Both the wait and the rule: the rule alone covers the case.

**Escape hatch.** A tool still missing after the re-probes is reported as
missing: the worker snoozes or fails with what it saw, as before.
