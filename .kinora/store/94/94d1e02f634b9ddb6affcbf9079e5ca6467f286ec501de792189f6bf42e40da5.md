# Spec — a context has a measures tab derived from its existing records

**Contract.** The selected context's console adds a **measures** tab beside head and trace, including in the URL fragment and phone selection. One store query derives lease starts, claims (pull plus handoff), submit attempts, completed items, blocked attempts, releases, re-claims (attempts after the first), lease ends by reason, submissions with downgraded lines, and inbox entries. Historical submissions without a downgrade count show that measure as unknown rather than zero.

The tab says that bare CLI sessions and phone-only actions are not mechanically recorded. It never invents those counts from unrelated events.

**Chosen.** A read-only projection over the context store, computed in the engine and rendered by the existing console trace pane. The dogfood record remains the context and its submissions; this tab is a view, not another record.

**Rejected.** A separately maintained metrics document, and treating missing historical downgrade metadata as zero.

**Escape hatch.** Future measurements need a recorded event or metadata field first; then the projection can add them.
